#### Important (Should Fix)
- **Six of the twelve FFI functions have zero runtime behavioral coverage in Python/Node/wasm.** `prn_build`, `prn_service`, `prn_region`, `prn_org`, `prn_resource_type`, `prn_resource_id` are exposed on all three shims but are exercised by **no** parity corpus and **no** replay test — the three corpora only cover `canonicalize`/`error_kind`, `mint_uuid7`, and the two `cedar` accessors. Their only guards are the compile-time `Exact&lt;&gt;` type-parity check (which catches *signature* drift, not *behavioral* drift) and the Rust kernel proptest (which tests `paigasus_kernel::Prn`, not the shim wrappers). In particular the spec §5 marshalling contract — `prn_org`/`prn_region` map `None`/empty → `""`, and `prn_build` maps `""` org → `None` not `BadOrg` — is asserted nowhere at runtime in any of the three bound languages. This is spec-consistent (spec §6 deliberately defines only three corpora) and the risk is low because I confirmed the three shims are line-for-line identical, but for a whole-branch view it is the one place where a future single-shim edit to an accessor could silently diverge in behavior without failing CI. Closing it is cheap: a small `prn_fields.json` corpus (input → service/region/org/type/id, plus a couple of `prn_build` round-trips including the empty-org case) replayed in all three languages. Files: `rs/crates/bindings/*/src/lib.rs`, `rs/crates/libs/paigasus-kernel-parity/src/lib.rs`, `py/.../tests/test_parity.py`, `ts/.../tests/*.test.ts`.

#### Minor (Nice to Have)
- **`wasm-getrandom-free` gate can go false-green if `cargo tree` fails for a non-getrandom reason.** `moon.yml:111` runs `if cargo tree ... -i getrandom &gt;/dev/null 2&gt;&amp;1; then ... exit 1; fi`. The check treats *any* non-zero exit as "getrandom absent" — but `cargo tree -i &lt;pkg&gt;` also exits non-zero when the package name is mistyped, the manifest is broken, or graph resolution fails, in which case the guard passes green while actually verifying nothing (and it swallows stderr). Harden by asserting the graph resolves first, e.g. `cargo tree -p paigasus-wasm --target wasm32-unknown-unknown -e no-dev | grep -q getrandom &amp;&amp; { echo "..."; exit 1; }` with `set -o pipefail`, so a broken tree command fails loudly instead of silently disarming a security-relevant invariant. (Note: the spec §8/§2.6 also called for the gate to include a `cargo build --target wasm32-unknown-unknown`; that buildability is instead covered by the main `:build` graph, which is acceptable, but the gate itself is tree-only.)
- **Python `mint()` uses `/` where spec §5 specifies `//`.** `py/.../__init__.py:23` computes `time.time_ns() / 1_000_000` (true division → fractional float) vs the spec's `time.time_ns() // 1_000_000`. Behaviorally identical after the shim's `f64 → u64` truncation, so not a bug — noting only for spec-text fidelity.
- Dead-but-harmless `.map_err(...)` on the `u8::from_str_radix` call in every `parse_rand_hex` (the bytes are already validated as `[0-9a-f]`, so it can't fail). Not worth changing; clippy is green.
