- Logging privacy bar (load-bearing for metric label design): never log/label prompt/messages/body/keys; `principal`/`key_id`/`model` are OK (§1 G1, and `chat.rs:106-109` comment). **Do not put `model` as an unbounded metric label without cardinality thought** — it's caller-supplied.

**The gateway request path (for what to instrument):**
1. Body-size limit layer (`DefaultBodyLimit`, `http/mod.rs:66`) → over-limit = **413**.
2. **Authn** — `require_iam_auth` middleware (`auth.rs:49`): bearer extract → `Iam::introspect_api_key` (§4.2/D12). Failure mapping (`introspect_error`, `auth.rs:128`): unreachable→**503**, `Unauthenticated`/inactive→**401**, empty scope→**500**.
3. **Authz (self-query, D9)** — `Iam::is_authorized_self(caller_key, introspected_SA, "InvokeModel", scope_prn)` (`auth.rs:84`). Mapping (`authz_error`, `auth.rs:145`): deny→**403**, `PermissionDenied`→**500** (self-query bug), unreachable→**503**.
4. **Proxy** — strip caller headers, inject real key, forward to OpenAI `/v1/chat/completions` (`chat.rs:78`); non-stream returns status+JSON; **SSE stream** passthrough unbuffered with a mid-stream terminal-error adapter (`chat.rs:86-96`, `terminal_sse_error_stream` `chat.rs:137`). Upstream connect/transport→**502**, timeout→**504** (`chat.rs:98-101`).
5. One structured log line (`chat.rs:110`).

Natural gateway metric set: request counter by route/status-class, request-duration histogram (latency already measured), IAM-introspect/authz call counters+latency by outcome, upstream-call counter+latency by status, in-flight streams gauge, 413/401/403/502/503/504 counters.
