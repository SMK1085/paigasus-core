## Issues

**Important — inflight gauge leaks on a panicking handler** (`rs/crates/libs/paigasus-observability/src/http.rs:684-690`)
```rust
let inflight = gauge!(format!("{prefix}_http_inflight_requests"));
inflight.increment(1.0);
let started = Instant::now();
let resp = next.run(req).await;   // &lt;- if this panics, unwind skips the next line
inflight.decrement(1.0);
```
If the downstream handler (or an inner layer) panics, `next.run(req).await` unwinds past `inflight.decrement(1.0)` — Rust does not execute subsequent statements during unwinding unless run via a `Drop` impl. The gauge is then permanently off by one per panic, with no bound and no recovery short of process restart — directly the failure mode the review brief named as a focus point. No test exercises a panicking handler. Fix: wrap the gauge handle in an RAII guard so the decrement runs on drop (including during unwind), e.g. a small `struct InflightGuard(metrics::Gauge)` with `impl Drop { fn drop(&amp;mut self) { self.0.decrement(1.0); } }`, held across `next.run(req).await`.

**Important — `record_grpc` duplicates metric-name literals instead of using the `names` registry** (`rs/crates/libs/paigasus-observability/src/grpc.rs:595,602` vs. `rs/crates/libs/paigasus-observability/src/names.rs:846-847`)
`grpc.rs` hardcodes `"iam_grpc_requests_total"` / `"iam_grpc_request_duration_seconds"` rather than referencing `crate::names::IAM_GRPC_REQUESTS_TOTAL` / `crate::names::IAM_GRPC_REQUEST_DURATION_SECONDS`, even though this call site is not parameterized (unlike `http.rs`, which legitimately must build names dynamically from `prefix`) and could trivially use the consts. This defeats the stated purpose of the registry ("single source of truth… AND the dashboard/alert name-drift test"): a future rename in `names.rs` silently diverges from what `grpc.rs` actually emits, with nothing (compiler or test) to catch it. The implementer's report notes the hardcoding as a "concern for later units" (re: gateway prefix support) but doesn't address the drift risk itself. Fix: `counter!(crate::names::IAM_GRPC_REQUESTS_TOTAL, ...)` / `histogram!(crate::names::IAM_GRPC_REQUEST_DURATION_SECONDS, ...)`.

**Minor — `method` label sourced from the raw HTTP method, no allowlist** (`rs/crates/libs/paigasus-observability/src/http.rs:683`)
`req.method().as_str().to_owned()` is unbounded in principle — HTTP's method token grammar permits arbitrary extension methods, so a client hitting this layer directly (e.g. at a gateway edge, before any router-level method restriction) could mint new label values per request. Low likelihood/impact in practice (most requests never reach the handler with a non-standard verb), but worth a bounded fallback (match against the known verb set, else `"OTHER"`) if this layer is ever mounted ahead of request validation.

**Minor — `record_grpc`'s duration histogram isn't asserted by its test** (`rs/crates/libs/paigasus-observability/src/grpc.rs:640-652`)
The test only asserts on `iam_grpc_requests_total`/`service`/`method`/`grpc_status`; it never checks `out.contains("iam_grpc_request_duration_seconds")`. This exactly matches the brief's provided test code (not an implementer deviation), and the twin-line histogram call is low-risk, but it means the histogram side of the "record real behavior" claim is unverified here (contrast with `http.rs`'s test, which does check its duration histogram at `http.rs:733`).
