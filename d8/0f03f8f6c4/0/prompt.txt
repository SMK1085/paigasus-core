**Minor** — `rs/crates/services/paigasus-gateway/Cargo.toml:81-83` (dev-dependency `metrics-exporter-prometheus`). The stated rationale ("`tests/metrics.rs` names `PrometheusHandle` directly to call `.render()`") is factually wrong — grepped the whole crate tree and `tests/metrics.rs` never names `PrometheusHandle` anywhere; every `handle` binding is untyped (`let handle = paigasus_observability::init(...)`). `PrometheusHandle::render()` is an *inherent* method (verified in the vendored source, `metrics-exporter-prometheus-0.18.3/src/recorder.rs:413`), so Rust resolves it via type inference without requiring the defining crate to be a direct dependency. Verified empirically: built an isolated worktree at this commit, removed the dev-dependency line, and `cargo test -p paigasus-gateway --test metrics` compiled and passed all 4 tests unchanged. `cargo machete` doesn't flag it (apparent tool limitation, not evidence it's needed). Not a functional defect — harmless bloat plus an inaccurate code comment — but worth pruning before merge; leaving it invites the same false pattern to be copied into a future service crate.

**Minor** — `rs/crates/services/paigasus-gateway/src/adapters/http/auth.rs` — the `iam_result` mapping (the one item this review's brief specifically flagged as a named risk) has no direct or indirect test asserting its label output. The pre-existing decision-table tests (`introspect_unavailable_returns_503`, `introspect_connect_failure_returns_503`, `authz_permission_denied_returns_500`, `authz_unauthenticated_returns_401`, etc., `auth.rs:355-431`) already exercise every `IamError` variant through `require_iam_auth` — which now calls `record_iam_call`/`iam_result` on every one of those paths — but none of them installs a recorder or renders `/metrics` to check the resulting `result` label. Cheap fix: either a small `#[test] fn iam_result_maps_...()` table directly on the private fn, or extend a couple of the existing `auth.rs` decision-table cases to also call `paigasus_observability::init(...)` and assert the rendered label.
