# SMA-371 — Local git hooks (lefthook + commitlint) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add local git hooks that reject non-Conventional-Commit messages (`commit-msg`) and non-conforming branch names (`pre-push`) on contributor machines, owned by lefthook and validated by a shared `@paigasus/commitlint-config`.

**Architecture:** lefthook (pinned via proto, on `$PATH`) is the sole owner of `.git/hooks/*`; Moon `vcs.hooks` stays empty. `commit-msg` runs commitlint from the git-root cwd via the explicit `ts/node_modules/.bin/commitlint` path; `pre-push` runs a small POSIX script that validates the current branch. Install is triggered by a resilient `prepare` script plus a `moon run repo:install-hooks` task on a new root-level `repo` Moon project.

**Tech Stack:** lefthook, commitlint (`@commitlint/cli` + `@commitlint/config-conventional`), pnpm workspace (rooted at `ts/`), Moon 2.2.5, proto.

**Design spec:** `docs/superpowers/specs/2026-05-29-sma-371-local-git-hooks-design.md`

**Branch:** `feature/sma-371-local-git-hooks-commit-msg-conventional-commits-branch-name` (already checked out).

> **Note on commit validation during this plan:** the hooks are not installed until Task 7. Earlier task commits are therefore unvalidated, but every commit message below is a valid Conventional Commit (valid type + allowed scope), so commits made after Task 7 still pass.

**Files:**

- [ ] **Step 1: Write the failing test first**

Create `.lefthook/pre-push/check-branch.test.sh`:
```bash
#!/usr/bin/env bash
# SPDX-License-Identifier: Apache-2.0
set -uo pipefail
here="$(cd "$(dirname "$0")" && pwd)"
sut="$here/check-branch.sh"
fail=0

assert() { # $1 desc  $2 want_exit  $3 branch
  "$sut" "$3" >/dev/null 2>&1
  code=$?
  if [ "$code" -ne "$2" ]; then
    echo "FAIL: $1 (branch='$3' got=$code want=$2)"
    fail=1
  else
    echo "ok:   $1"
  fi
}

assert "feature/ passes"        0 "feature/sma-371-local-git-hooks"
assert "main allow-listed"      0 "main"
assert "dependabot allow-listed" 0 "dependabot/npm_and_yarn/commitlint-19"
assert "sven/ rejected"         1 "sven/foo"
assert "uppercase rejected"     1 "feature/SMA-371"
assert "bare slug rejected"     1 "wip"

exit "$fail"
```

- [ ] **Step 2: Run the test to verify it fails**

- [ ] **Step 3: Write the validator**

Create `.lefthook/pre-push/check-branch.sh`:
```bash
#!/usr/bin/env bash
# SPDX-License-Identifier: Apache-2.0
#
# Reject pushing a branch whose name doesn't match the Paigasus convention.
# Validates the CURRENT branch (HEAD); takes an optional branch arg for testing.
set -euo pipefail

branch="${1:-$(git symbolic-ref --short HEAD 2>/dev/null || true)}"

# Detached HEAD / no branch: nothing to validate.
[ -z "$branch" ] && exit 0

# Allow-list: default branch and bot branches.
[ "$branch" = "main" ] && exit 0
case "$branch" in
  dependabot/*) exit 0 ;;
esac

# Enforce: feature/<lowercase-slug>.
if printf '%s' "$branch" | grep -Eq '^feature/[a-z0-9._-]+$'; then
  exit 0
fi

cat >&2 <<EOF
✖ Branch name "$branch" is not allowed.
  Branches must match:  ^feature/[a-z0-9._-]+\$
  Rename this branch:   git branch -m feature/<slug>
  (main and dependabot/* are exempt; CI enforces the same rule server-side.)
EOF
exit 1
```

- [ ] **Step 4: Run the test to verify it passes**

Run:
```bash
chmod +x .lefthook/pre-push/check-branch.sh
.lefthook/pre-push/check-branch.test.sh; echo "exit=$?"
```
Expected: every line `ok:`, final `exit=0`.

## Task 4: lefthook.yml

**Files:**
- Create: `lefthook.yml`

- [ ] **Step 1: Create the hook definitions**

Create `lefthook.yml` (no SPDX header — config):
```yaml
# Local git hooks for paigasus-core. lefthook is the sole owner of .git/hooks
# (ADR-0010); Moon vcs.hooks is intentionally empty. Install via:
#   moon run repo:install-hooks   (or automatically on `pnpm install` in ts/)

# Don't re-validate replayed commits during interactive rebases / merges.
skip:
  - merge
  - rebase

commit-msg:
  commands:
    commitlint:
      run: |
        # Bots commit/push directly; CI is their authoritative gate.
        case "$(git config user.email)" in
          *\[bot\]@*) exit 0 ;;
        esac
        if [ ! -x ts/node_modules/.bin/commitlint ]; then
          echo "✖ commitlint not found. Run 'proto install' then 'pnpm install' in ts/." >&2
          exit 1
        fi
        ts/node_modules/.bin/commitlint --edit {1} --config ts/commitlint.config.cjs

pre-push:
  commands:
    branch-name:
      run: |
        case "$(git config user.email)" in
          *\[bot\]@*) exit 0 ;;
        esac
        .lefthook/pre-push/check-branch.sh
```

- [ ] **Step 2: Commit**

```bash

git commit -m "feat(repo): add lefthook.yml (commit-msg + pre-push hooks)"

```markdown
### Local development setup (git hooks)

Local git hooks enforce the commit-message and branch-name conventions before
CI sees them. They're managed by [lefthook](https://lefthook.dev) (pinned in
`.prototools`) and run [commitlint](https://commitlint.js.org) from `ts/`.

**Order matters:** run `proto install` *before* installing workspace
dependencies, so the lefthook binary is on `$PATH`:

```bash
proto install                 # installs moon, buf, lefthook
moon run repo:install-hooks   # one-time: writes .git/hooks/{commit-msg,pre-push}
```

`pnpm install` (in `ts/`) also installs the hooks via a `prepare` script, so
contributors who touch `ts/` get them automatically. Pure-Rust / pure-Python
contributors should run the `moon run repo:install-hooks` step above.

- **commit-msg** rejects non-Conventional-Commit messages.
- **pre-push** rejects branches not matching `^feature/[a-z0-9._-]+$`
  (`main` and `dependabot/*` are exempt).
- **Emergency bypass:** `git commit --no-verify` (CI still enforces the rule).
- **GUI git clients** (VS Code, IntelliJ, etc.) often launch with a stripped
  `$PATH`; if commits fail there with "command not found", add your proto shim
  directory (`~/.proto/shims`) to the client's environment.
```
