# Bootstrap `py/` uv workspace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold the Python workspace under `py/` — a virtual uv workspace root with shared dev tooling and all tool config, four inert stub packages that are first-class Moon projects, and a `py` parent Moon project that runs the workspace-wide quality gates.

**Architecture:** uv workspace rooted at `py/` (no `[project]` table — virtual root). Four packages under `py/packages/*`, each a uv member built by the `uv_build` backend and registered as its own Moon project. A `py` parent Moon project owns the `lint`/`format`/`typecheck`/`test` gates, which run from cwd `py/` (the only place bare tooling resolves the single root config) via `uv run`. A guarded `conftest.py` keeps `pytest` green while the workspace has zero tests.

**Tech Stack:** uv 0.11.16, `uv_build` backend, basedpyright (`typeCheckingMode = "all"`), ruff (lint + format), pytest + anyio, Moon 2.2.5 (`unstable_python` 3.12.13 + `unstable_uv`).

**Spec:** `docs/superpowers/specs/2026-05-26-sma-358-py-uv-workspace-design.md`

**Prerequisites:** Work on branch `feature/sma-358-bootstrap-py-uv-workspace-with-basedpyright-ruff-config` (already created). `proto install` has provisioned Moon. uv/Python toolchains download on first `moon run` (network needed once).

**Note on TDD:** This is infrastructure scaffolding — there is no application code to test-drive. The "test" for each task is running the real tool/gate (`uv sync`, `uv run pytest`, `uv run basedpyright`, `uv run ruff`, `moon run …`) and asserting its exit code / output. Tasks build incrementally so each is independently verifiable.

- [ ] **Step 2: Write `py/conftest.py`**

```python
# SPDX-License-Identifier: Apache-2.0
# TODO(SMA-379): remove this shim once at least one package has tests; until then it keeps the
# empty workspace green. The on-disk guard means it does NOT mask a "discovery broke" regression
# in a package that previously had tests.
import pytest


def pytest_sessionfinish(session: pytest.Session, exitstatus: int) -> None:
    if exitstatus == pytest.ExitCode.NO_TESTS_COLLECTED and not any(
        p.is_dir() for p in session.config.rootpath.glob("packages/*/tests")
    ):
        session.exitstatus = 0
```

## Execution amendments (post-review decisions)

Two things surfaced during Task 5 that the as-written tasks above did not anticipate; the executed
result reflects these decisions:

1. **Moon project-ID `-py` suffix.** Moon derives project IDs from the directory leaf, so the Python
   `paigasus-kernel` package collided with the Rust `paigasus-kernel` crate. Each Python *package*
   `moon.yml` therefore carries an explicit `id: 'paigasus-<name>-py'` (`paigasus-proto-py`,
   `paigasus-kernel-py`, `paigasus-ml-py`, `paigasus-workflows-py`). The `py` parent project keeps id
   `py` (gates remain `moon run py:<task>`). Rust crates get the mirror `-rs` suffix in a follow-up
   (**SMA-380**) — not touched here. So Task 1's package `moon.yml` and Task 5's `py/packages/*`
   wiring include that `id` line.

2. **`py/.python-version` pins `3.12.13`.** Raw `uv` was selecting Python 3.14 (newest satisfying
   `requires-python >=3.12`), and Moon's `uv run` reused that venv — nothing ran on the pinned 3.12.
   Adding `py/.python-version` (`3.12.13`, matching `.moon/toolchain.yml`) makes both raw uv and Moon
   build/run the venv on 3.12.13. Added during Task 5; `uv.lock` was unaffected (deps resolve for
   `>=3.12`).

Follow-up issues filed from this work: **SMA-378** (PyPI publish metadata for proto/kernel),
**SMA-379** (remove the pytest exit-5 shim once tests exist), **SMA-380** (suffix Rust Moon ids `-rs`).
