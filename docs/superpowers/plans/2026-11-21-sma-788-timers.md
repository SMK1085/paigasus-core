# SMA-788 Timers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the agent host timers: a `timer` table, agent follow-ups and cron schedules, a
scheduler loop that writes a deterministic `agents.timer.fired` event into the inbox, four Helikon
tools, caps and a creation budget.

**Architecture:** All timer rules live in the pure core crate `paigasus-agent-host-core`: the
types, the cron syntax check, the civil-time walk with the DST rules, `plan_fire`, the run
workspace and the tool texts. The service crate `paigasus-agent-host` adds migration m0004, a
transactional inbox insert, `PgTimerStore` (with `apply_in` for SMA-790), `PgScheduler`, the
loop, the event builder, the `[timers]` config and the Helikon tool adapter. A new proto message
`TimerFired` is the event `data`.

**Tech Stack:** Rust 2024, `croner` 4.0.3 (feature `jiff`, no default features), `jiff` 0.2.46
(feature `tzdb-bundle-always`), SeaORM 2 (raw statements), `paigasus-helikon` 0.6.12, buf and
protobuf-es / betterproto2 codegen, testcontainers Postgres 16, cargo-nextest, Moon 2.6.5.

**Spec:** `docs/superpowers/specs/2026-11-21-sma-788-timers-design.md` (approved; S1–S7 and the
§12 calls are final). "§x" below is a section of that spec. Read the section that a task names.

### Measured facts that change the spec

These are true in the code and the crates. The plan uses them. Task 17 writes them into the spec.

- **Berlin's repeated hour is 02:00–02:59**, not 01:00–01:59. On 2026-10-25 the clock goes from
  03:00 CEST back to 02:00 CET. So `0 * * * *` fires at `2026-10-25T00:00:00Z` (02:00 CEST) and
  `2026-10-25T01:00:00Z` (02:00 CET). The §6.2 R3 and §14.1 text "01:00 CEST and 01:00 CET in
  Berlin" is wrong. New York repeats 01:00–01:59 on 2026-11-01.
- **The literal R3 occurrence step skips slots.** For `*/15 * * * *`, "the next result is the same
  civil slot with `second`" jumps from 02:00 CEST to 02:00 CET and skips 02:15–02:45 CEST. Task 3
  uses an ordered walk (the "fold rule" below) that gives the R3 result for `0 * * * *` and fires
  all eight slots of `*/15 * * * *` in instant order.
- **Helikon has no `ToolEffect::Read`.** The variants are `ReadOnly`, `Write` and `SideEffect`.
  `list_timers` uses `ReadOnly`.
- **Rust has no proto3 JSON for `agents/v1`.** `paigasus-proto` is prost only, with no serde. The
  Rust test checks the event `data` against the message descriptor (`FILE_DESCRIPTOR_SET`). The
  TypeScript test parses the same JSON with `fromJson(TimerFiredSchema, …)`.
- **`croner` cannot refuse its extensions.** `CronParser` has `seconds`, `year`, `dom_and_dow`,
  `alternative_weekdays` and `sloppy_ranges`. `Seconds::Disallowed` refuses any field count other
  than 5, so it refuses a seconds field and a year field. Its name replacement is private, so the
  pre-check replaces month and weekday names itself.
- **`PgTimerStore` has no caller in the binary before SMA-790.** `main.rs` builds the
  `TzResolver` and `PgScheduler` only. A built and unused store is an unused variable.
- **`schemaversion` and `actorprn` of the timer event.** IAM writes `schemaversion` as an integer
  (`paigasus-iam/src/adapters/events/cloud_event.rs`). The NATS path drops `actorprn` for a
  host-made event (SMA-787 §9.3). So the timer event has `schemaversion = 1` (integer),
  `datacontenttype = "application/json"`, and no `actorprn` and no `subject` (§17).
- The release profile has no `panic` key, so it is `unwind`. Task 12 adds a `compile_error!`
  guard under `#[cfg(not(panic = "unwind"))]`.

## Review Focus

1. **A follow-up `at` without an offset** (`2026-11-22T09:00`), a date only, or a `Z` time with a
   fraction. Expected: the first two give a refusal that names "RFC 3339 with an offset"; the
   fraction is rounded up to the next second. Pinned in Task 6 (`at_forms`).
2. **A zone name in another case or as a link** (`europe/berlin`, `US/Eastern`, `UTC`). Expected:
   accepted, and stored as the canonical IANA name, so the list text and the event `tz` are stable.
   Pinned in Task 1 (`zone_names_are_canonical`).
3. **Cron spelling variants**: tabs and double spaces, lowercase names (`mon-fri`, `jan`), `7` for
   Sunday, `@HOURLY`. Expected: accepted with the same slots as the plain form. Pinned in Task 1
   (`spelling_variants_match_the_plain_form`).
4. **`in_seconds` at the edges**: `-1`, `0`, `i64::MAX`, a float `60.5` and a string `"60"`.
   Expected: a refusal text, never a panic or an overflow. Pinned in Task 5 (`in_seconds_edges`)
   and Task 6 (`argument_types`).
5. **A note of exactly 1000 multi-byte characters** (`"é".repeat(1000)`, 2000 bytes). Expected:
   accepted by `Note::parse` and by the Postgres `CHECK (char_length(note) <= 1000)`; 1001
   characters is refused by both. Pinned in Task 2 and Task 7.

    — the first gap in seconds between two consecutive civil slots in `[from, from + days)` that is
    below `min_secs`, or `None`.
  - `pub const WALK_BOUND: u32 = 10_000;` and `pub const CIVIL_GAP_WINDOW_DAYS: u32 = 366;`

`resolve` uses `TimeZone::to_ambiguous_timestamp(c).offset()`:
`AmbiguousOffset::Unambiguous { offset }` → `Single(offset.to_timestamp(c)?)`;
`Gap { after, .. }` → `Single(T)` with `T = tz.following(after.to_timestamp(c)?).next()` →
`.timestamp()` (R1: the first instant after the gap, 03:00 local, never `compatible`);
`Fold { before, after }` → `first = before.to_timestamp(c)?`, `second = after.to_timestamp(c)?`,
`T = tz.following(first).next().timestamp()`, `fold_start = after.to_datetime(T)`,
`fold_end = before.to_datetime(T)`. A `None` from `following` or a jiff error is `WalkError::Tz`.

`next_after` is this algorithm (§6.2 with the fold rule; the 25-hour clamp is step 2):

```text
cur = fired
floor = tz.to_datetime(now) - 25 hours
if cur.civil < floor: cur = Slot { civil: floor, second: false }
repeat at most `bound` times:
    cand = step(cur)
    t = instant(cand)
    if t > now: return (cand, t)          # R4: an equal instant (a gap) never fires twice
    cur = cand
return Err(BoundExceeded { bound })

step(cur):                                # the fold rule (R3), interval patterns only
    if is_interval and resolve(cur.civil) is Fold { fold_start, fold_end }:
        n = next_civil_after(cur.civil)
        if cur.second:     return Slot { civil: n, second: n < fold_end }
        if n < fold_end:   return Slot { civil: n, second: false }
        s = first civil slot at or after fold_start    # find_next_occurrence(&fold_start, true)
        return if s < fold_end { Slot { civil: s, second: true } } else { Slot { civil: n, second: false } }
    return Slot { civil: next_civil_after(cur.civil), second: false }
```

A fixed-hour pattern never sets `second` (R2, R3).
