### Adjudication of the declared deviation
The transport codes are written as an explicit `Unavailable | DeadlineExceeded | Internal` arm **plus** a separate `_` arm (both → `IamUnavailable`), instead of the brief's `… | _`. **Justified and correct.** A wildcard inside an or-pattern trips clippy's `wildcard_in_or_patterns` (a `complexity` lint in `clippy::all`, which the workspace denies with `-D warnings`), so the brief's literal form wouldn't compile clean. The two-arm form is idiomatic, documents the expected retryable codes, and is exhaustive. `match_same_arms` (which would flag the identical bodies) is `pedantic`, not in `clippy::all`, so it does not fire — consistent with the reported clean clippy run.

## Issues

**Minor**
- `error.rs:499-501` — the `Internal` variant doc says "details are logged, not echoed", but the middleware performs no logging at all. For a security-critical auth path, emitting zero telemetry on auth failures/500s is an observability gap (denials are IAM-audited server-side per the facts doc, and the brief doesn't mandate gateway logging, so this is not a spec miss — but the doc slightly overstates current behavior). Consider adding `tracing` on the 500 paths in a later task and softening the comment.
- `auth.rs:104` (forward-looking, **not a G5 defect**) — the inbound `Authorization: Bearer &lt;caller-key&gt;` header is left on `req` when handed to `next.run`. Fine within the gateway's trust boundary (the intended channel is `CallerContext`), but G7 must ensure it does **not** forward inbound headers verbatim to the OpenAI upstream, or the caller's Paigasus key would egress. Worth a one-line note in the G7 brief.
