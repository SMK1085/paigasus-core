  ## 1. CORE module layout and the `Protocol` abstraction
  
  `CORE/src/lib.rs` declares private modules: `anthropic body decider interceptor json limits openai protocol report sse turn types`. It re-exports `parse_body`, `Interceptor`, `Action`, `Metric`, `ToolCallDecider`, `AllowAll`, `DecisionContext`, `Limits`, `OnFailure`, `parse_request`, `ToolTurn`, `Format`, `ToolCall`, `Decision`, `BlockCode`, `HoldKey` and `notice_line`. The crate is sans-IO: no tokio or axum, and its only dependencies are bytes, serde, serde_json (with `preserve_order`), sha2 and thiserror.
  
  **The `Protocol` trait** is in `CORE/src/protocol.rs:~92`. It is `pub(crate)` and `Send`. A format implements it, and `Interceptor::new` picks the implementation with a `match` on `Format` (`interceptor.rs:96-105`, `Box<dyn Protocol>`).
  - `step(&mut self, rec: Record, verdicts: &Verdicts) -> Result<Step, StepError>` classifies one SSE record and assembles tool calls. It returns:
    - `Step::Frame{frame, opened: Vec<HoldKey>, completed: Vec<(HoldKey, Vec<ToolCall>)>, reports}`
    - `Step::End(Frame)` for `[DONE]` or `message_stop`
    - `Step::UpstreamError(Frame)`
    - `StepError::{Malformed, Deviation(&'static str)}`
  - `incomplete() -> Vec<HoldKey>` lists holds that opened and never completed. They are truncated at the end of the stream.
  - `release(frame, verdicts) -> Vec<Bytes>` returns the bytes for one released frame. It may return none (a dropped frame) or several (a notice first). This is where the rewrite happens.
  - `closing(verdicts) -> Vec<Bytes>` returns notices still owed when the stream has no end marker.
  - `known_calls(hold) -> Vec<(u32, String)>` is used for reports of `BlockAll` holds.
  - `unframed(rec) -> Bytes` is pass-through framing.
  - `retained()` is test-only.
  
  **Supporting types in `protocol.rs`:**
  - `Frame{event: Option<&'static str>, payload, value: Option<Value>, touches: Vec<HoldKey>}`. `touches` is the set of holds a frame carries data of. A frame is released only when every hold it touches is decided.
  - `Verdict::{AllowAll, PerCall(Vec<Decision>), BlockAll(BlockCode), PassThrough}`, with `block_code(slot)`. A missing decision is a block with `DeciderError`.
  - `Deviation(&'static str)` is a violation of the canonical form.
  - `MAX_IDENTIFIER_BYTES = 1024`.

  ## 2. Service crate (`SVC`)
  
  **Hexagonal layout:**
  - `domain/` is pure: `CallerContext`, `Credential`, `resolve_org`, and `limits.rs` (sliding window, budget periods, and the `LimitStore` port).
  - `application/` holds `limits.rs` (`Limits::admit`) and `charge_guard.rs` (`ChargeGuard`).
  - `adapters/` holds the transport and infrastructure code:
    - `http/` has `auth.rs`, `chat.rs`, `interception.rs`, `usage.rs`, `dto.rs`, `error.rs` and `bytes.rs`.
    - `iam/` has the `Iam` port (`#[async_trait] trait Iam`, `iam/client.rs:75`) and `IamClient`.
    - `limits/` has `memory.rs` and `redis.rs`, implementing `LimitStore`.
    - `openai/` has `OpenAiClient`, the egress adapter.
  
  **Route registration** is in `adapters/http/mod.rs:107`. This is the only protected route; a `/v1/responses` route would join it:
  
  `Router::new().route("/v1/chat/completions", post(chat::chat_completions)).route_layer(auth).route_layer(body_limit)`
  
  - `auth` is `from_fn_with_state(AuthState{iam, dpop_enabled}, require_iam_auth)`.
  - `body_limit` is `DefaultBodyLimit::max(max_request_bytes)`.
  - `/healthz`, `/readyz` and the service-info route (which uses `require_authenticated` only) sit in other groups.
  - The router also applies `http_metrics_layer("gateway")` and `CorrelationLayer`, then `.with_state(AppState)`.
  - `AppState` fields: `iam: Arc<dyn Iam>`, `openai: Arc<OpenAiClient>`, `max_request_bytes`, `capabilities`, `limits: Option<Arc<Limits>>`, `dpop_enabled`, `tool_interception: Option<Arc<ToolInterception>>`.
  
  **Handler flow** (`chat.rs:86`, `chat_completions`):
  1. Extract `CallerContext`, which the auth middleware attached.
  2. Parse a copy of the body into `ChatCompletionRequest{model, stream, messages, extra}` (`dto.rs`). The original bytes go upstream verbatim.
  3. Refuse streaming if `capabilities.chat_stream` is off.
  4. `state.limits.admit(&caller)` runs the rate limits and budget pre-check, returning a `ChargeGuard` or a 429. It runs only when `[limits]` is configured.
  5. `guard.set_request_estimate(usage::request_tokens_estimate(&messages, body.len()))`, `set_ids`, `mark_sent`.
  6. If interception is on, build `parse_request(Format::OpenAiChat, &body)` and a `DecisionContext`.
  7. `state.openai.chat_completion(body, stream)` (`openai/client.rs:306`) POSTs to `{base_url}/v1/chat/completions`. It sets only the Bearer key, Content-Type and Accept headers, so the caller's headers never cross. It returns `ChatResponse::Full{status, body}` or `ChatResponse::Stream{status, stream: BoxStream<Result<Bytes>>}`.
     - Non-stream has a first-byte timeout. Stream has connect and idle timeouts only.
     - Dropping the stream cancels the upstream request.
  8. Non-stream success: `usage::non_stream_usage(&body)` runs on the ORIGINAL body. It returns `Reported(usage.total_tokens)` or `Completion(estimate)`, and the result goes to `guard.set_reported` or `set_completion_estimate`. Then `interception::intercept_body` parses, decides and rewrites. A malformed body under `block` gives 502 `tool-interception-malformed-response`. The decisions go in the `paigasus-tool-decisions` header.
  9. Stream success: with interception, `interception::intercepted_stream(stream, guard.take(), ti, ctx, turn, TERMINAL_SSE_ERROR)` is used. Without it, `terminal_sse_error_stream` is used.
  10. Non-2xx upstream responses are forwarded verbatim, with `guard.mark_no_charge()`.
  
  **Usage and billing:**
  - `UsageScanner` (`usage.rs:84`) reads a COPY of the SSE bytes. It adds 1 token per data record, and the last `usage.total_tokens` wins. It is fed through `feed_scan` and `finish_scan` (`chat.rs:307` and `:317`) into `guard.set_stream_progress(records, reported)`. Usage appears in a stream only if the client sent `stream_options.include_usage`.
  - The scanner reads `/usage/total_tokens` and `choices[]`. The Responses API puts usage at `response.usage` in the `response.completed` event, with `input_tokens`, `output_tokens` and `total_tokens`, so a new scanner or reader is needed (INFERRED from the shapes).
  - `ChargeGuard::tokens()` returns the reported total, else request estimate plus completion estimate, capped at `MAX_TOKENS_PER_CHARGE`. The charge happens in `Drop`: `limits.store().charge(ticket, tokens, now)` and the `gateway_tokens_charged_total{source}` metric. So billing is settled when the response body is dropped or ends, in every path.
  - `request_tokens_estimate` reads `messages[].content`. A Responses request has `input`, not `messages`, so this needs a variant.
  - `dto.rs` requires `messages`, so a Responses DTO is needed too.
  - `Limits::admit` takes only `&CallerContext`. The rate limit and budget are per principal and per org, and are not endpoint-specific. Some log strings and `"chat completion metered"` are chat-specific wording.
  
  **Streaming relay** (`adapters/http/interception.rs`):
  - The `Relay` unfold state owns the upstream, the `UsageScanner`, the guard, the `Interceptor`, a decide queue and one pending decision future (P-5), and a sleep timer.
  - Loop: `feed_scan`, then `Interceptor::push`. On an upstream error: `finish_scan`, then `abort()`, which emits the terminal frame. On end: `finish_scan`, then `finish()`.
  - `relay(format, …)` is generic over `Format`. `intercepted_stream` fixes it to OpenAI. Unit tests drive Anthropic through `relay`.
  - The `Metric`-to-name mapping is `record(m)`.
  
  **Config:** `[tool_interception]` is `ToolInterceptionConfig` in `config.rs`, with `enabled=false` default. `config.rs:40/49` doc comments say "on `/v1/chat/completions`". `OpenAiConfig{base_url, api_key (SecretString), extra_ca_bundle_path}` is at `config.rs:116`.

  ## 8. Implications for invariant I1 (INFERRED from the code above)
  1. The final source differs per SDK. Python uses `completed.output`, Node uses the snapshot replaced by `completed`, and LangChain uses `added` + deltas. The gateway must make `added`, deltas, `done` and `completed.output` agree. This covers `name`, `call_id` and `arguments`, and also the item `id`.
  2. In Python, identity is `(type, call_id)`. A `completed.output` call with a new `call_id` is accepted without a raise. The gateway must decide Allow for every call that is in `completed.output` and in every `output_item.done`.
  3. `added.arguments` is non-empty in LangChain: `args=item.arguments` is concatenated with all deltas. A non-empty `added.arguments` plus deltas gives a different string than Python or Node would accumulate. Keep `added.arguments=""` or keep all views consistent.
  4. LangChain routes by `item_id`, Node validates `item_id == output item id`, Python ignores `item_id`. A delta whose `item_id` differs from the item at its `output_index` is a divergence trap. Emit consistent ids.
  5. A partial call is visible in LangChain at every prefix, in the Node snapshot, and in Python's `failed` or `incomplete` event output. If the gateway raises or truncates mid-call, all three expose partial calls unless the call is withheld until decided.
  6. Client-executed items beyond `function_call` (`custom_tool_call`, `computer_call`, `local_shell_call`, `shell_call`, `apply_patch_call`, `tool_search_call` with `client`, `mcp_approval_request`) need the same decide-before-emit treatment. LangChain hides some of them from its tool-call surface, but the other SDKs expose them.
